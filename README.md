# folio — CV Generator

**Ein Lebenslauf sollte sich dem Inhalt anpassen – nicht umgekehrt.**

folio ist ein quelloffener Lebenslauf-Generator für Schülerinnen und Schüler auf Lehrstellensuche, Berufseinsteigende und erfahrene Berufstätige. Persönliche Angaben, Ausbildung, Schnupperlehren, berufliche Stationen und weitere Inhalte werden strukturiert erfasst. Die Anwendung übernimmt Layout und automatische Aufteilung auf A4-Seiten, damit der Lebenslauf bei Änderungen nicht jedes Mal neu formatiert werden muss.

## Warum ich folio brauche

Ich bin in der zweiten Sekundarschule und beschäftige mich gerade mit meiner Berufswahl. Dazu gehören auch Schnupperlehren – und nach jeder neuen Erfahrung möchte ich meinen Lebenslauf aktualisieren.

Eigentlich klingt das einfach: Eine neue Station mit Datum, Betrieb und Tätigkeiten hinzufügen. In Word war das aber oft mühsamer als erwartet. Plötzlich verrutschten Texte, Abstände passten nicht mehr, und aus einer kleinen Ergänzung wurde eine längere Formatierungsarbeit.

Zusammen mit meinem Vater habe ich mir auch andere Lebenslauf-Generatoren angeschaut. Einige waren kostenlos verfügbar. Bei einigen davon gab es aber Einschränkungen, z.B. wo sich ein Foto platzieren lässt oder wie genau wir Abstände einstellen können.

Ausserdem war für uns nicht bei allen Angeboten klar ersichtlich, wo meine eingegebenen Daten gespeichert und wie sie weiterverarbeitet werden. In einem Lebenslauf stehen viele persönliche Angaben. Deshalb möchte ich verstehen können, was mit ihnen passiert, und sie möglichst unter eigener Kontrolle behalten.

Daraus entstand die Idee: **Warum kann ich nicht einfach eine Schnupperlehre hinzufügen und das Programm kümmert sich selbst um den Rest?**

Zusammen mit meinem Vater arbeite ich an folio, einem Lebenslauf-Generator, der Inhalte und Gestaltung voneinander trennt. Damit soll es einfacher werden, meinen Lebenslauf während der Berufswahl aktuell zu halten. Und weil nicht nur Schülerinnen und Schüler dieses Problem kennen, stellen wir das Projekt als Open Source auch anderen zur Verfügung.

## Für wen?

- **Schülerinnen und Schüler:** Schulbildung, Schnupperlehren, Interessen und erste Projekte ohne aufwendiges Nachformatieren festhalten.
- **Berufseinsteigende:** Erfahrungen ergänzen und die Darstellung auf verschiedene Bewerbungen abstimmen.
- **Erfahrene Berufstätige:** Umfangreiche Laufbahnen, Projekte und Kompetenzen übersichtlich und auch mehrseitig darstellen.

## Unser Ansatz

- **Inhalt vor Formatierung:** Neue Station erfassen, statt Textblöcke manuell verschieben.
- **Getrennte Daten und Gestaltung:** Lebenslauf und Layout sind strukturiert gespeichert; Vorlagen und Einstellungen lassen sich verändern, ohne Inhalte neu einzugeben.
- **Gestaltungsfreiheit ohne Word-Chaos:** Schriftarten, Farben, Abstände, Spalten, Bilder und Abschnitte sind konfigurierbar; die Seitenaufteilung übernimmt die Anwendung.
- **Lesbare Dokumente:** Die PDF-Ausgabe soll für Menschen ansprechend und als Text extrahierbar sein. Eine universelle ATS-Kompatibilität wird nicht behauptet.
- **Lokal und unter eigener Kontrolle:** In der aktuellen Version werden Daten im Browser bearbeitet und können als Projektdatei exportiert werden. Eine serverseitige Lösung ist eine mögliche spätere Ausbaustufe.

## Gemeinsam mit meinem Vater und KI entwickelt

folio ist ein gemeinsames Projekt mit meinem Vater. Am Anfang stand etwas Konzeptarbeit: Welches Problem möchten wir lösen, und wie soll die Anwendung dabei helfen? Danach ging es an die Umsetzung mit **KI-gestützten Programmierwerkzeugen**. Dabei lassen wir Code durch KI erzeugen und überarbeiten und nutzen sie auch zur Analyse und Verbesserung.

Ich möchte offen damit umgehen: Es wäre nicht richtig, die gesamte Implementierung als eigene Programmierleistung darzustellen. Der Beitrag liegt darin, das ursprüngliche Problem zu beschreiben, Anforderungen zu formulieren, Ideen auszuprobieren, Entscheidungen zu treffen und zu prüfen, ob die Anwendung im Alltag wirklich hilft.

Ich möchte dabei Schritt für Schritt mehr darüber lernen, wie Software entsteht und wie ich selbst etwas dazu beitragen kann. Was wir gemeinsam entwickeln und was ich persönlich gemacht und verstanden habe, möchte ich auch ehrlich erklären können.

## Aktueller Entwicklungsstand

Die erste Version ist ein lokaler, deutschsprachiger React-/MUI-Editor mit A4-Live-Vorschau, automatisch aufgeteilten Seiten, konfigurierbarer Studio-Vorlage, JSON-Projektdateien und PDF-Ausgabe über den Browser. Der Funktionsumfang wird unten im Detail dokumentiert; nicht alle langfristig geplanten Funktionen sind bereits umgesetzt.

## Starten

Voraussetzung: Node.js 22.13+ oder 24 und npm.

```sh
npm ci
npm run dev
```

Danach die im Terminal angezeigte Adresse öffnen (normalerweise <http://127.0.0.1:5173>).

```sh
npm run build        # TypeScript check and production build
npm run preview      # Preview the local production build
npm run format:check # Check consistent formatting
npm run format       # Format TypeScript, TSX, JSON and CSS
npm run lint         # Lint the application, renderer, core and tests
npm test             # Model, import and pagination tests
npx playwright install chromium
npm run test:browser
```

## Was bereits funktioniert

- Formulare für persönliche Angaben, Kurzprofil, Ausbildung, Erfahrung, Projekte, Kenntnisse, Sprachen und Interessen.
- «Über mich» bleibt auch bei längeren Texten ein zusammenhängender Absatz mit gleichmässigem Zeilenabstand. Absatzabstand entsteht durch selbst eingefügte Zeilenumbrüche; längere Texte werden anhand der tatsächlichen Textzeilen über A4-Seiten verteilt. Vorschau und PDF verwenden dieselben Umbrüche.
- Kontaktangaben mit passenden Icons für Adresse, E-Mail, Telefon, Website und freiwilligen Zivilstand. Strasse und Ort bilden einen gemeinsamen Adressblock; leere Angaben werden ausgeblendet.
- Optionales Geburtsdatum unter «Persönliches»: taggenaues Kalenderdatum, im Kontaktbereich mit Kalender-Icon als `TT.MM.JJJJ` dargestellt. Leer lassen entfernt die Angabe vollständig. Das Datum wird strukturiert gespeichert; bestehende Lebensläufe erhalten kein erfundenes Geburtsdatum.
- Einträge hinzufügen, entfernen und per Tastatur bedienbaren Buttons umordnen.
- Stationsdaten standardmässig taggenau (`15.03.2022`), je «Von»/«Bis» auf Monatsgenauigkeit (`03/2022`) umschaltbar. «Bis» darf leer bleiben: Für Schnuppertage oder eintägige Informationsveranstaltungen erscheint dann nur das «Von»-Datum, ohne Zeitraumstrich. Der Knopf «Enddatum entfernen» leert auch eine bereits begonnene Eingabe vollständig. «Bis heute / noch laufend» wird nur für laufende Stationen aktiviert. Beim Umschalten der Genauigkeit bleibt ein eingegebener Tag gespeichert. Bestehende Monats-/Jahresangaben behalten ihre Genauigkeit; fehlende Tage werden nicht ergänzt.
- Live-Vorschau auf A4; kurze und lange, vollständig synthetische Beispiel-Lebensläufe sowie ein leerer Start.
- Die Prozentanzeige über der Vorschau öffnet Zoomstufen von 25 bis 400 %, einschliesslich 100 %. Manuell gewählter Zoom bleibt beim Ändern der Fenstergrösse erhalten; «Vorschau einpassen» passt wieder automatisch an die verfügbare Breite an. Für die tatsächliche A4-Papiergrösse am Bildschirm das Lineal-Symbol wählen: Vergleichslinie mit einem echten Lineal messen, gemessene Millimeter eingeben und «A4 1:1 anzeigen» anklicken. Die Kalibrierung wird lokal für den Browser gespeichert; nach Monitor- oder Browserzoomwechsel über das Prozentmenü «Bildschirm kalibrieren …» wiederholen. 100 % allein entspricht der A4-Grösse in Browser-Einheiten, deren physische Grösse vom Bildschirm abhängt. Zoom und Kalibrierung sind reine Vorschau-Einstellungen; Projektdatei und A4-PDF bleiben unverändert.
- Datenbasierte Studio-Vorlage: Farbe, Verlauf, drei lokal ausgelieferte Schriften, Schriftgrösse, Zeilenabstand, Ränder, Abschnittsabstände, Seitenleistenposition und -breite.
- Design-Einstellungen in der Reihenfolge Profilfoto, Header, Typografie, Aufteilung & Abstände und Abschnitte. Die fünf Bereiche sind als deutlich abgegrenzte Karten mit Nummern und kurzen Inhaltsangaben dargestellt. Ein Klick auf die Bereichsüberschrift klappt die Einstellungen ein/aus; das funktioniert auch mit Enter oder Leertaste. «Alle ausklappen» und «Alle einklappen» bleiben beim Scrollen erreichbar. Beim ersten Öffnen sind alle Bereiche geöffnet; danach wird der Klappzustand pro Browser-Tab für die Sitzung gemerkt, auch beim Wechsel zwischen Inhalt und Design oder beim Neuladen. Eingaben, Lebenslauf und JSON-Export bleiben beim Einklappen erhalten. Unter «Design → Header» lässt sich die Akzentfarbe über Vorgaben oder eine freie Farbauswahl einstellen.
- Der zentrale Button «Zurücksetzen» neben «Öffnen» ist in Inhalt, Design und mobiler Vorschau erreichbar; auf schmalen Bildschirmen erscheint er als Rücksetz-Symbol. Er öffnet eine Sicherheitsabfrage. Standardmässig stellt erst «Jetzt zurücksetzen» alle Designwerte der Studio-Vorlage wieder her: Foto-/Headergestaltung, Typografie, Abstände, Farben, Kenntnisse-Darstellung sowie Abschnittsüberschriften, Reihenfolge, Platzierung und Sichtbarkeit. Lebenslaufdaten und Bilddateien bleiben dabei erhalten; das Profilfoto wird ausgeblendet und das Headerbild abgewählt. Unter «Header → Gespeichertes Headerbild» lassen sich vorhandene Bilder erneut auswählen. Die zusätzliche, bei jedem Öffnen ausgeschaltete Option «Auch Lebenslaufdaten und Bilder zurücksetzen» entfernt bei Bestätigung sämtliche persönlichen Angaben, Einträge und Bilder und öffnet einen leeren Lebenslauf zur Bearbeitung. Abbrechen, Escape oder ein Klick ausserhalb der Abfrage verändert nichts. Der bestätigte Reset wird lokal und beim Projekt-Export gespeichert; Vorschau-Zoom, Bildschirmkalibrierung und Klappzustände bleiben erhalten.
- Header-Abschluss: gerade, Welle, Schräge, Bogen oder Spitze; Formhöhe von 4 bis 16 mm. Unter «Design → Header» auswählbar. Welle und Schräge lassen sich horizontal spiegeln. Farbe, Verlauf und Hintergrundbild folgen der vollständigen Kontur ohne abgeschnittene Endpunkte.
- Ausbildung, Erfahrung und Projekte in der Hauptspalte mit Punkten, Punkten samt Verbindungslinie oder ohne Markierung. Unter «Design → Aufteilung & Abstände → Stationen markieren» einstellbar. In der Seitenleiste erscheinen diese Abschnitte immer ohne Punkte, Zeitachse und deren seitlichen Einzug, unabhängig von links/rechts. Beim Zurückverschieben in die Hauptspalte gilt wieder die gespeicherte Markierung.
- Bei «Punkte mit Verbindungslinie» läuft die Zeitachse in der Hauptspalte über Seitenumbrüche weiter: bis zum Ende des Inhaltsbereichs oberhalb des Fussbereichs und auf der Folgeseite ab Inhaltsbeginn. Dies gilt bei geteilten Beschreibungen und zwischen Stationen desselben Abschnitts, auch ohne Beschreibung. Beim Abschnittsende entfällt die Verlängerung. «Nur Punkte» und «Ohne Markierung» zeigen keine Verbindungslinie. Die Seitenleiste bleibt auch auf Folgeseiten ohne Zeitachse.
- Zeitachse über «Position der Zeitachse» horizontal von −10 bis +12 mm verschieben. Hauptüberschriften (auch «Über mich» und «Erfahrung») sind linksbündig an der Linienmitte ausgerichtet. Punkte, Linie, Überschriften und Texte rücken gemeinsam; die Position wird gespeichert und auch im PDF verwendet.
- Unter «Design → Aufteilung & Abstände» den Abstand zwischen Zeitachsenmitte und Stationstext in der Hauptspalte von 2 bis 14 mm einstellen (Standard 3,75 mm). Der zusätzliche Abstand nach einer Station ist von 0 bis 12 mm wählbar (Standard 1,5 mm) und gilt für Ausbildung, Erfahrung und Projekte in beiden Spalten, einschliesslich Stationen ohne Beschreibung. Absätze innerhalb einer Station behalten ihren Abstand. Vorschau, Pagination und PDF berücksichtigen die Werte; Hauptspaltenüberschriften bleiben an der Zeitachse ausgerichtet. Seitenleisteninhalt bleibt vom Zeitachsenversatz und -textabstand unabhängig.
- Abschnitte ein-/ausblenden, umordnen und zwischen Hauptspalte und Seitenleiste verschieben.
- Unter «Design → Abschnitte» die Überschrift jedes Abschnitts einschliesslich Kontakt frei bearbeiten, beispielsweise «Erfahrung» zu «Berufserfahrung». Je Überschrift ist die Schriftgrösse von 8 bis 20 pt einstellbar (Standard 9 pt), unabhängig von der Schriftgrösse des Inhalts. Ein leeres Titelfeld verwendet die Standardüberschrift. Die Vorlage zeigt Überschriften weiterhin in Grossbuchstaben. Eigene Titel und Grössen bleiben beim Umordnen, Verschieben und Ausblenden erhalten und werden mit dem Layout gespeichert. Vorschau, Seitenaufteilung und textbasiertes PDF berücksichtigen auch mehrzeilige Überschriften.
- Unter «Design → Abschnitte → Kontakt» lässt sich «Kontaktüberschrift anzeigen» ausschalten. Die erste Kontaktangabe beginnt dann auf Höhe der Überschrift «Über mich», ohne leeren Platz für die ausgeblendete Kontaktüberschrift. Ein eigener Kontakttitel und seine Grösse bleiben für das spätere Einblenden gespeichert; die zugehörigen Bearbeitungsfelder sind solange deaktiviert. Der gemeinsame Beginn der folgenden Inhaltsspalten bleibt erhalten. Die Einstellung gilt auch für das PDF.
- Unter «Design → Abschnitte → Kontakt» lassen sich Geburtsdatum, Adresse, E-Mail, Telefon, Zivilstand und Website mit Pfeiltasten frei sortieren. Leere Angaben behalten ihre Position und werden übersprungen; Adresse und Ort bilden eine gemeinsame Angabe. Eigene Regler steuern den Zeilenabstand innerhalb der Angaben (1–2,4) und den Abstand zwischen ihnen (0–8 mm). Das Geburtsdatum verwendet ein Tortenpiktogramm. Reihenfolge und Abstände werden gespeichert und im PDF verwendet.
- Unter «Design → Aufteilung & Abstände → Stationskopf: Datum, Titel & Arbeitgeber» sind die Zeilenabstände von Datum, Stationstitel und Arbeitgeber/Institution separat einstellbar (1–2,4). Die Zwischenräume nach dem Datum und vor dem Arbeitgeber lassen sich von 0 bis 8 mm einstellen. Steht das Datum zuletzt oder der Arbeitgeber zuerst, entfällt der jeweilige Zwischenraum. Die Werte gelten für Erfahrung, Ausbildung und Projekte in beiden Spalten, unabhängig von Beschreibungstext und Stationsabstand.
- Kontakt und «Über mich» bilden standardmässig einen gemeinsamen Einstieg, auch ohne Trennlinien. Die längere Seite bestimmt seine Höhe; darunter beginnen die ersten gewählten Abschnitte gemeinsam (beim beruflichen Beispiel Kenntnisse und Erfahrung). Auch ein mehrseitiger Einstieg wird zuerst abgeschlossen. Reihenfolge und Spaltenzuordnung der übrigen Abschnitte bleiben erhalten.
- Optional unter «Design → Aufteilung & Abstände»: «Freien Platz bei ausgeblendetem Über mich nutzen». Wenn das Kurzprofil ausgeblendet oder leer ist, beginnt die Hauptspalte direkt unter dem Header; die Seitenleiste fliesst unter den Kontaktangaben weiter. Der Einstiegsabstand und eine eingeschaltete Headerlinie gelten dann nur innerhalb der Seitenleiste. Auf einer neuen Seite entfällt dieser lokale Übergang. Ein sichtbares Kurzprofil stellt automatisch den gemeinsamen Einstieg wieder her. Neue und migrierte Projekte starten mit ausgeschalteter Option; Speicherung, Import und PDF berücksichtigen die Auswahl.
- Unter «Design → Aufteilung & Abstände» sind «Abstand zum Header» und «Abstand nach Kontakt & Über mich» unabhängig von 0 bis 30 mm einstellbar (neue Projekte: 15 bzw. 5 mm). Der Headerabstand gilt auf der ersten Seite unterhalb des Headers bzw. eines überlappenden Fotos. Der gemeinsame Abstand zum folgenden Inhalt gilt auch ohne Linien; mit Linien kommen deren obere/untere Abstände hinzu. Die Werte sind unabhängig vom Seitenrand, werden gespeichert und im PDF verwendet. Ohne Einstieg oder ohne Folgeinhalt entfällt der gemeinsame Zwischenabstand.
- Unter «Design → Aufteilung & Abstände» lassen sich «Kopfzeile auf Folgeseiten anzeigen» und «Fusszeile anzeigen» unabhängig ausschalten. Der grosse gestaltete Header auf Seite 1 bleibt sichtbar. Ohne kleine Kopfzeile gewinnen Folgeseiten 15 mm Inhaltshöhe; ohne Fusszeile gewinnen alle Seiten zusätzlich 8 mm. Vorschau und PDF verteilen den Inhalt automatisch neu; die Seitenränder bleiben erhalten. Beide Einstellungen werden mit dem Projekt gespeichert.
- Optionale «Horizontale Trennlinien» unter «Design → Aufteilung & Abstände»: Die erste Linie unter Kontakt und «Über mich» überspannt beide Spalten. Weitere Linien trennen Abschnitte nur innerhalb ihrer Spalte. Ausschalten entfernt die Linien und ihre zusätzlichen Linienabstände; die gemeinsame Ausrichtung und der eingestellte Abstand nach dem Einstieg bleiben erhalten.
- Beginnt ein Abschnitt auf einer neuen Seite, entfällt seine Trennlinie einschliesslich ihrer oberen/unteren Linienabstände. Das gilt in beiden Spalten und für die gemeinsame Linie, wenn der folgende Inhalt auf eine neue Seite wechselt. Der separat eingestellte Abstand nach Kontakt und «Über mich» bleibt erhalten. Linien zwischen Abschnitten auf derselben Seite bleiben sichtbar. Vorschau und PDF berücksichtigen dies bereits bei der Seitenaufteilung.
- Bei eingeschalteten Trennlinien sind oberer und unterer Freiraum unabhängig von 0 bis 15 mm wählbar (neue Projekte: jeweils 5 mm). Die breite «Headerlinie» unter Kontakt und «Über mich» hat dafür zwei eigene Regler, unabhängig von den weiteren Trennlinien innerhalb der Spalten. Vorhandene Abstände innerhalb von Stationen bleiben bestehen. Abschnittslinien der Hauptspalte beginnen an der Zeitachsenmitte; in der Seitenleiste beginnen sie immer am linken Textrand. Ohne Markierung beginnen sie am linken Textrand. Automatisch reichen sie bis zum rechten Textrand; «Eigene Länge der Abschnittslinien» erlaubt 10–100 % dieses Platzes. Die gemeinsame Linie nach Kontakt und «Über mich» behält immer die volle innere Seitenbreite. Vorschau, Seitenaufteilung und PDF berücksichtigen die Einstellungen.
- Unter «Design → Header» lässt sich «Namensdarstellung im Header» zwischen Vorname/Nachname untereinander und nebeneinander umstellen. Sehr lange Namen umbrechen bei Bedarf sicher, auch mit einem Foto. Unter «Design → Typografie» reicht der allgemeine Zeilenabstand von 0,9 bis 1,8; beide Regler verwenden Schritte von 0,05. Zusätzlich lässt sich ein eigener Zeilenabstand von 0,9 bis 2,4 für die physisch linke Spalte unterhalb von Kontakt und «Über mich» aktivieren. Er gilt auch dann links, wenn die Seitenleiste rechts steht, und auf Folgeseiten. Kontakt und «Über mich» sowie die eigenen Einstellungen der Stationsköpfe bleiben unverändert. Abschnittsüberschriften verwenden in beiden Spalten den allgemeinen Zeilenabstand, damit ihre Schriftgrundlinien beim Verstellen des linken Fliesstexts ausgerichtet bleiben. Die Vorschau behält beim Verstellen ihre Scrollposition, damit die rechte Spalte nicht durch automatische Browser-Verankerung mitbewegt wird. Ausgeschaltet gilt der allgemeine Zeilenabstand.
- Unter «Design → Aufteilung & Abstände → Stationskopf: Datum, Titel & Arbeitgeber» lassen sich die drei Angaben per Pfeilen frei sortieren. Die Reihenfolge gilt für Erfahrung, Ausbildung und Projekte in beiden Spalten und auch für den auslesbaren PDF-Text. Der Jobtitel bleibt stärker hervorgehoben; leere Angaben werden übersprungen. Der Zeitachsenpunkt sitzt mittig zur ersten sichtbaren Zeile des Stationskopfs und berücksichtigt deren Schriftgrösse und eigenen Zeilenabstand. Das gilt auch bei fehlenden Datums-/Arbeitgeberangaben und mehrzeiligen Titeln. Der Linienanfang folgt dem Punkt.
- Unter «Design → Header» verschiebt «Header nach oben verschieben» den gestalteten Header um 0–20 mm nach oben. «Name im Header vertikal verschieben» verschiebt den Namensblock einschliesslich Beschriftung und Untertitel zusätzlich um −15 bis +15 mm (negativ nach oben, positiv nach unten, 0 mm bisherige Position). Beim Verschieben des Namensblocks bleiben Headerhöhe und -grenze, Bildausschnitt, Profilfoto und der Inhalt darunter unverändert. Die Textbewegung wird auf den sichtbaren Bereich zwischen Seitenrand und Header-Abschluss begrenzt. Die neutrale Headerhöhe berücksichtigt weiterhin Textlänge und Fotogrösse. Gewonnener Platz wird bei der Seitenaufteilung für Inhalt genutzt. Der Abstand unterhalb des Headers bleibt separat einstellbar. «Schriftfarbe im Header» erlaubt eine eigene Farbe für Name, Untertitel und Beschriftung, auch bei gesetztem Hintergrundbild. Kleine Kopfzeilen auf Folgeseiten, Akzentfarbe und Fotorahmen bleiben unabhängig. Die Einstellungen werden gespeichert und im PDF verwendet.
- Optionales Hintergrundbild unter «Design → Header»: PNG/JPEG bis 4 MB, lokal neu kodiert und mittig auf den Header zugeschnitten. Mit gesetztem Bild entfällt der Farb-/Verlaufsuntergrund im Header. Bildtransparenz von 0 bis 100 % lässt den weissen Seitenhintergrund durchscheinen (0 % vollständig sichtbar, 100 % unsichtbar). Die separate Abdunklung von 0 bis 80 % verbessert die Lesbarkeit; sie wird zusammen mit dem Bild ausgeblendet. Text und Profilfoto bleiben deckend. Die Akzentfarbe gilt weiterhin für Überschriften und Stationspunkte. Entfernen des Bilds stellt den gewählten Farb-/Verlaufsheader wieder her.
- Optionales Profilfoto (PNG/JPEG), lokal neu kodiert; Kreis, Rechteck oder abgerundete Form. Unter «Design → Profilfoto» links/rechts platzierbar. «Foto im Header vertikal verschieben» bewegt das ganze Foto samt Rahmen um −15 bis +15 mm (negativ nach oben, positiv nach unten). Ohne Überlappung bleibt die Bewegung zwischen Seitenrand und Header-Abschluss; Headergrenze, Name und Hintergrundbild verändern sich dabei nicht. Die separate «Überlappung der Headergrenze» von 0 bis 20 mm bleibt erhalten und kann mit der Verschiebung kombiniert werden. Ragt das Foto dadurch weiter nach unten, erhält der Inhalt entsprechend mehr Abstand. Bei sichtbarem Foto links stehen Name und Untertitel rechtsbündig. Die Fotobreite ist von 24 bis 60 mm einstellbar; die Rahmenbreite von 0 bis 4 mm, mit frei wählbarer Farbe. «Einpassen» bzw. «Ausfüllen» und horizontale/vertikale Ausschnittregler ändern weiterhin nur das Bild innerhalb des festen Rahmens. Alle Einstellungen werden gespeichert und gelten auch im PDF.
- Die Ausschnittregler bewegen das Foto auch dann, wenn es eine Achse exakt ausfüllt (z. B. hochformatiges Foto mit «Einpassen» vertikal). 50 % zentriert es; beim Verschieben können weisse Freiflächen entstehen. Rahmen, Fotogrösse und Headerposition bleiben dabei fest.
- Kenntnisse unterstützen einen optionalen qualitativen Kenntnisstand, eine Freitextbeschreibung und eine freie Kategorie. Im Formular lassen sich fünf Stufen auswählen oder eigene Bezeichnungen eingeben; eine Selbsteinstufung ist nicht erforderlich. Unter «Design → Abschnitte → Kenntnisse» sind «Text» (bisheriger Standard), «Progressbar» und «Detailliert» wählbar. Kenntnisstände, Beschreibungen und Kategoriegruppierung lassen sich dort schalten. Die Konfiguration wird unabhängig von den CV-Daten in `layout.skills` gespeichert.
- Optionale eigene Progressbar unter «Inhalt → Kenntnisse» und «Inhalt → Sprachen» pro Eintrag einschalten. Die Beherrschung lässt sich per Regler mit Wertanzeige als ganze Zahl von 0 bis 100 einstellen; 0 ist ein leerer und 100 ein voller Balken. Der eigene Wert erscheint als Balken in Vorschau und PDF und bleibt mit dem Eintrag gespeichert. «Prozentangabe anzeigen» schaltet die Zahl neben dem Balken pro Eintrag separat ein oder aus; diese Darstellungseinstellung bleibt beim Umordnen, Speichern und Import erhalten. Kenntnisstand und Sprachniveau bleiben unabhängig davon Freitext. Ohne eigene Einschätzung bleibt die bisherige Darstellung erhalten.
- Die Balkenzuordnungen je Kenntnisstand unter «Design» greifen für Kenntnisse ohne eigenen Wert und zeigen relative, bearbeitbare grafische Längen; sie sind keine Kompetenzprozente. Qualitative Einstufungen bleiben als auslesbarer Text sichtbar. Ohne Kenntnisstand oder passende Zuordnung entfällt der Balken. «Langjährige Erfahrung» und individuelle Bezeichnungen bekommen standardmässig keinen Balken; eigene Zuordnungen können ausdrücklich eingerichtet werden. Lange Beschreibungen werden in beiden Spalten automatisch auf Seiten verteilt. Sprachen behalten ihre Freitexteingabe für Muttersprache und GER-Stufen A1–C2.
- Unter «Referenzen» lassen sich mehrere Kontaktpersonen mit Name, Funktion, Organisation, E-Mail, Telefon und optionaler Adresse erfassen, sortieren und löschen. Der Abschnitt erscheint standardmässig in der linken Seitenleiste. Unter «Design → Abschnitte → Referenzen» sind Überschrift, Schriftgrösse, Reihenfolge, Spalte und Sichtbarkeit einstellbar; die Seitenleiste lässt sich wie bisher links oder rechts anordnen. Leere Personen und Felder werden weggelassen. Kurze Kontaktkarten bleiben auf einer Seite zusammen; lange Angaben können über Seiten hinweg fliessen. Referenzen werden mit dem JSON-Projekt gespeichert und als auslesbarer Text ins PDF übernommen.
- In den Beschreibungen von Erfahrung, Ausbildung und Projekten stehen «Fett» und «Aufzählung» zur Verfügung: Wörter markieren und «Fett» wählen (auch Strg/Cmd+B); eine oder mehrere Zeilen mit «Aufzählung» als Liste formatieren. Erneutes Anwenden entfernt die Formatierung. Direkt eingebbar sind `**fett**` und `- Listenpunkt` (auch `* ` oder `• `). Enter setzt eine Liste fort, Enter auf einem leeren Punkt beendet sie. Absätze und Listen lassen sich mischen; auch lange Listenpunkte behalten ihre Formatierung über Seitenwechsel. Vorschau und PDF zeigen dieselbe Formatierung, der PDF-Text bleibt auslesbar. HTML wird als Text dargestellt.
- Automatische Speicherung in `localStorage` und versionierter JSON-Import/-Export inklusive effektivem Layout, Vorlage, Foto und Headerbild. Ungültige und unbekannte Felder werden abgewiesen, nicht still entfernt.
- Textbasierte PDF-Ausgabe über eine getrennte Druckansicht mit demselben Renderer und denselben A4-Seiten. Vorschau-Zoom, Editor und eingeblendete Hinweise beeinflussen den Export nicht.
- Responsive Bearbeitung und Vorschau, ohne Konto oder externe Schrift-/Bildabrufe.

**PDF speichern:** «PDF exportieren» wählen, dann im Druckdialog «Als PDF speichern». A4, keine Ränder, Skalierung 100 %, Browser-Kopf-/Fusszeilen ausschalten und Hintergrundgrafiken aktivieren. Chromium ist die getestete Referenz. Andere Druckdialoge können abweichen.

**Daten sichern:** Die automatische Speicherung ist browser- und installationsgebunden. «Projekt speichern» lädt eine portable JSON-Datei herunter. Diese kann mit «Öffnen» wieder geladen werden. Beim Wechsel auf einen neuen Beispiel-Lebenslauf bietet der Dialog vorher einen Dateiexport an. JSON-Dateien enthalten persönliche Angaben und gegebenenfalls Profilfoto und Headerbild.

## Struktur

```text
apps/web/src/             React/MUI-Oberfläche, Formulare, lokale Speicheranbindung
packages/core/src/        gemeinsame Zod-Schemas, Typen, synthetische Beispiele
packages/renderer/src/    MUI-freies HTML, Layoutvariablen, Pagination, Druck-CSS
templates/modern/        versionierte Vorlage und Layout als JSON
tests/                   Browser-/PDF-Integrationstests
docs/                    Architekturentscheidungen
```

Die Tests schreiben Screenshots, JSON-Dateien und tatsächliche PDFs nach `test-results/` (nicht versioniert). PDF-Tests prüfen Seitenzahl, Vollständigkeit, Hauptspalten-Reihenfolge und Textauslesbarkeit mit allen drei Schriften.

Eigene Lebensläufe, Fotos und Exporte innerhalb des Projektordners bitte unter `private/` ablegen; dieser Ordner ist von Git ausgeschlossen. Ebenso ausgeschlossen sind Abhängigkeiten, Build-/Testausgaben, Coverage, lokale Umgebungsdateien und Logs. Die eingebauten JSON-Vorlagen, synthetischen Testdaten und `package-lock.json` werden dagegen versioniert.

Auch lokale Editor-/KI-Einstellungen (`.vscode/`, `.idea/`, `.history/`, `.codex/`, `.agents/`), AWS-Konfiguration (`.aws/`), private Schlüsseldateien, `.cvpkg`-Pakete sowie die Ordner `data/`, `uploads/`, `exports/` und `backups/` im Projektstamm sind ausgeschlossen. Persönliche JSON-, PDF- und Bilddateien ausserhalb dieser Ordner sind nicht automatisch geschützt. Zugangsdaten und Tokens gehören nie in versionierte Dateien; eine `.env.example` darf nur Platzhalter enthalten. Vor einem Commit mit `git status` und `git diff --cached` prüfen, welche Dateien und Inhalte aufgenommen werden. `.gitignore` wirkt nicht rückwirkend auf bereits versionierte Dateien und lässt sich mit `git add -f` umgehen.

## Bewusste Grenzen dieses Entwurfs

- Kein Backend, keine Anmeldung und keine serverseitige Speicherung. Der Entwicklungsserver lauscht standardmässig nur auf Loopback. Vor öffentlichem Hosting sind Deployment und Datenschutz separat zu planen.
- PDF wird im Browser erzeugt. Ein automatisierter Fastify-/Playwright-Exportdienst folgt in M2.
- JSON-Projektformat `folio-json` Version 1, CV-Schema Version 8, Layoutschema Version 23 und Vorlagenschema Version 2 (Vorlage 1.1.0), noch kein ZIP-basiertes `.cvpkg`. CVs der Versionen 1–7 werden explizit migriert. Eigene Kompetenzwerte starten dabei ohne Bewertung (null); qualitative Sprach- und Kenntnisstände werden nicht in Prozentwerte umgerechnet. Kenntnisse aus Versionen 1–6 erhalten leere Beschreibungen und Kategorien; vorhandene Bezeichnungen und Kenntnisstände bleiben erhalten. Für Versionen 1–5 starten Referenzen leer. Bisher wörtlich dargestellte Sonderzeichen in Stationsbeschreibungen werden maskiert, damit deren Darstellung erhalten bleibt. Für Versionen 1–3 gilt weiterhin: Das Geburtsdatum bleibt leer; ein fehlender Zivilstand bleibt leer und vorhandene Datumsgenauigkeiten bleiben erhalten. Layouts der Versionen 1–22 werden beim Laden explizit migriert. Eigene Kompetenzbalken zeigen dabei zunächst weiterhin ihre Prozentangabe. Der kompakte Einstieg ohne Kurzprofil bleibt dabei ausgeschaltet. Der neue Fotoversatz startet bei 0 mm; bestehende Fotopositionen, Überlappung und Bildausschnitte bleiben erhalten. Für Versionen 1–19 startet der Versatz des Namensblocks bei 0 mm; bestehende Headerpositionen bleiben erhalten. Für Versionen 1–18 bleiben Namen untereinander, die linke Spalte folgt dem allgemeinen Zeilenabstand und Stationsköpfe behalten Datum–Titel–Arbeitgeber als Reihenfolge. Für Versionen 1–17 bleibt die Headerposition bei 0 mm, die Header-Schriftfarbe bei Weiss. Versionen 1–16 behalten Kenntnisse als Text mit sichtbarem Kenntnisstand. Fehlende Skills-Konfigurationen werden auf diesen Standard aufgelöst. Versionen 1–15 erhalten zudem den Abschnitt Referenzen am Ende der Seitenleiste (bei Vorlagen ohne Seitenleiste in der Hauptspalte). Vorlagen der Version 1.0.0 werden auf 1.1.0 migriert und erhalten die neue bekannte Komponente. Die breite Headerlinie übernimmt die bisherigen Trennlinienabstände, Kontaktreihenfolge und bisherige Kontaktabstände bleiben erhalten. Datum und Arbeitgeber übernehmen den gespeicherten globalen Zeilenabstand; Stationstitel und deren Zwischenräume behalten ihre bisherigen Werte. Für Versionen 1–13 gilt weiterhin: Kopf- und Fusszeile bleiben dabei eingeschaltet. Versionen 1–12 behalten eine sichtbare Kontaktüberschrift. Versionen 1–11 behalten die bisherigen Standardüberschriften mit 9 pt; vorhandene eigene Titel und Grössen bleiben erhalten. Versionen 1–10 übernehmen den bisherigen Seitenrand als Headerabstand und den gespeicherten Abschnittsabstand als gemeinsamen Abstand nach dem Einstieg. Die stets gemeinsame Ausrichtung und der neue Zwischenabstand können die Seitenaufteilung ändern. Layouts 1–9 erhalten zudem ihren gespeicherten Abschnittsabstand als oberen und unteren Trennlinienabstand sowie automatische Linienlänge. Layouts 1–8 behalten ausgeschaltete Trennlinien. Versionen 1–7 erhalten 3,75 mm Textabstand sowie 1,5 mm zusätzlichen Stationsabstand. Versionen 1–6 behalten ein vollständig sichtbares Headerbild (0 % Transparenz). Versionen 1–5 behalten Header ohne Spiegelung. Versionen 1–3 behalten Fotos rechts ohne Überlappung; ein Headerbild wird nicht ergänzt. Bisherige Fotogrösse (34 mm), weisser Rahmen (1,2 mm) und mittiger Zuschnitt werden beibehalten. Versionen 1/2 behalten die bisherige Position der Zeitachse (0 mm). Version 1 behält zudem den geraden Header und die Darstellung ohne Stationspunkte. Neue Lebensläufe starten mit Welle und Punkten samt Linie. Unbekannte Versionen werden abgewiesen.
- Ein Template mit geometrischer Dekoration, optionalem Foto und Headerbild. Ausschnittregler für das Headerbild, weitere Vorlagen und Zertifikate sind noch offen.
- Pagination misst DOM-Blöcke nach dem Laden der gebündelten Schriften. Zuerst wird der gemeinsame Einstieg verteilt; danach laufen Haupt-/Seitenleiste separat weiter. Der gemeinsame Beginn berücksichtigt Einstiegsabstand und optionale Linienabstände. Beschreibungen werden in kurze Textabschnitte zerlegt; mehrseitige Fortsetzungen nutzen auf Wunsch eine kleine Kopfzeile. Innerhalb jedes Bereichs steht im HTML die Hauptspalte vor der Seitenleiste, unabhängig von deren visueller Position. Das ist keine allgemeine ATS-Kompatibilitätsgarantie.
- Import: maximal 6 MB, bekannte Versionen/Felder, sichere Layoutwerte, ausschliesslich eingebettete PNG-Bilder. Foto-Uploads werden auf maximal 800 Pixel, Headerbilder auf 1600 Pixel Kantenlänge verkleinert; beide werden ohne Metadaten neu kodiert. Keine Skripte, HTML-, SVG- oder Remote-Assets. Ein künftiger Uploaddienst muss zusätzlich serverseitig validieren, vor dem Dekodieren Pixelgrenzen prüfen und Ressourcenlimits durchsetzen.

Die vollständige Produktspezifikation und nächsten Meilensteine stehen in [AGENTS.md](AGENTS.md).

Die englische [Dokumentation zur Codequalität](docs/code-quality.md) beschreibt die Prüfwerkzeuge, wichtige Annahmen von Pagination und Migrationen sowie den Vorher-/Nachher-Vergleich tatsächlicher PDFs. Bei Änderungen an Layout oder Seitenaufteilung lassen sich so Seitengeometrie, Textpositionen und gerenderte Ausgabe vergleichen.

Die [Modulaufteilung](docs/adr-037-modular-editor-core-and-renderer.md) beschreibt die getrennten Designbereiche und Editor-Abläufe sowie die Module für Schemas, Migrationen, Inhaltsblöcke, Header und Seitenmessung. Die bisherigen öffentlichen Einstiegspunkte bleiben erhalten.
